# Harness v0.6.0

本版合并尚未独立发布的 v0.5 与 v0.6 能力。服务端通过 GHCR 镜像交付；客户端提供 macOS Apple Silicon / Intel、Linux ARM64 / x64、Windows x64 安装包及 SHA256SUMS。

## 主要变化

- 首次使用可选择默认写入空间与读取范围，保存后后续调用沿用。无交互终端遇到多个候选时返回授权选项，不发送业务请求；已有默认配置继续使用。daily 在本地直接跳过。
- 管理后台增加用户名、密码与浏览器会话，支持保持登录、刷新恢复和主动退出；原独立管理员令牌继续可用。会话过期后可在原租户重新登录并继续处理页面内草稿和结果未知的写入。
- 增加显式多租户入口，各租户使用独立凭据、数据目录、空间目录、统计和会话。租户选择不授予访问权限。
- 后台统一知识列表，支持原空间编辑、差异预览、归档和恢复；提供路由诊断、按用途查看统计及模板结构检查。
- 保留 Markdown、按需读取、SHA-256 冲突保护、持久幂等和事务回滚；日常小任务没有新增必跑步骤。

## 升级与配置

1. 升级前备份完整 Store，使用发布产物部署，在构建机或 GitHub Actions 完成编译。
2. 现有单租户启动方式、凭据和空间保持兼容。部署新版本不自动迁移为多租户，不重建现有默认空间。
3. 需要账号登录时，按 [管理员登录](../ADMIN-LOGIN.md) 完成离线初始化，并通过私有环境配置；未配置账号时仍可使用原独立管理员令牌换取浏览器会话。生产 Cookie 保持 Secure，通过 HTTPS 同源访问。
4. 需要新租户时，按 [多租户配置](../MULTI-TENANCY.md) 显式配置独立 Store 和凭据。旧 Store 的迁移需要独立规划；没有在线注册或超级管理员开通页面。
5. 新客户端按 [首次接入](../CLIENT-SETUP.md) 配置。原有包装脚本、凭据注入和默认空间应保留。

## 已知边界

- 管理会话保存在进程内存，服务重启后需要重新登录；“保持登录”不跨服务重启。
- 新增租户需要配置并重启，同一进程内隔离不等于进程或主机隔离，每个 Store 仍只允许一个 writer。
- 模板检查验证结构；路由评测验证给定用例。二者不证明内容正确或真实任务净收益。
- 客户端包没有 macOS 公证或 Windows 代码签名。Linux 包要求 glibc 2.35 或更新版本。

本地验证范围见 [验证记录](../VALIDATION.md)。正式产物以本版本 Release 和 Actions 结果为准；云端实际运行版本需独立核验。
