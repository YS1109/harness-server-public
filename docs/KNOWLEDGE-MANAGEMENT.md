# 知识文档管理（v0.5）

管理员通过 `/admin` 的“知识文档”统一查看项目、专题、流程和模板。
空间作为来源和筛选条件，同路径的不同空间版本各占一行，不自动合并或迁移。
列表每页最多50份摘要（页面默认20份），不预读正文。项目筛选不会包含无项目的全局模板；
模板没有状态或核验日期，缺失字段不表示已经核验。Session、月志和执行记录仍使用专用流程。

## 编辑与归档

点击文档查看原文、来源、当前SHA和预算，再进入编辑。现有文档必须在原空间真实存在；
后台不会把继承版本复制进设备空间。已归档空间只读，先恢复空间才能写入。

编辑后点击“校验并预览差异”：服务在可丢弃副本中运行真实文档PUT、索引重建及全库校验，
返回目标和自动修改的项目入口的前后原文、SHA和预算。项目入口预算包含专题索引。
此操作不写HEAD、修订、审计或回执。页面以共同前后缀之外的完整替换区间呈现差异，
不是语义合并。修改草稿会使预览失效，保存必须重新确认。

确认后写回原空间，保存时重新检查SHA、受管身份、核验声明、凭据、预算和关联。
只自动更新编辑时间，不伪造核验日期。管理文档写入与审计同一个原子事务提交；
幂等重放不重复追加审计或产生修订。审计只记录管理员、动作和空间/逻辑路径，不记录正文。

项目、专题和流程支持ARCHIVED与ACTIVE切换。归档保留ID、路径和正文并退出默认检索；
归档项目入口同时影响该入口下专题的召回。恢复专题还需有ACTIVE项目入口。
原文模板没有状态，不能通过状态按钮归档；没有删除或跨空间移动操作。

409时页面保留草稿，并允许读取最新版本；手动合并后明确采用最新SHA，再重新预览。
网络失败或5xx时原请求和首次幂等键保留在当前页面内存，暂停其他写入；
显式重试复用完全相同的请求。不要刷新页面或退出以“重试”，这会丢失内存中的草稿和重试信息。
确定放弃后可以清除，但原请求可能已经保存，应先核对结果。

## 管理API

所有入口需要管理员身份：独立管理员Bearer凭据，或v0.6账号登录后的HttpOnly会话Cookie。浏览器写入要求同源及会话防伪校验，Agent凭据不能调用管理接口。多租户时每个操作都在所选租户中完成；不跨租户汇总或编辑。

| 方法 | 路径 | 行为 |
| --- | --- | --- |
| GET | `/admin/api/documents` | 可省略namespace跨目录空间分页；返回真实来源 |
| GET | `/admin/api/document?namespace=...&path=...` | 原空间原文、SHA、编辑能力和预算 |
| POST | `/admin/api/document/preview` | 校验保存副本，不持久化，无需幂等键 |
| PUT | `/admin/api/document` | 原空间保存，必须提供Idempotency-Key |
| POST | `/admin/api/route` | 指定1–8个读取空间的只读诊断 |
| POST | `/admin/api/check-template` | 指定原空间模板，检查输入文档，不保存 |

预览与保存共用请求：

```json
{
  "namespace": "shared",
  "path": "memory/project/demo/topic.md",
  "expected_sha256": "<读取的SHA-256>",
  "action": "edit",
  "content": "<完整Markdown>"
}
```

`action`为`edit`、`archive`或`restore`；状态操作不接受content。此版本编辑已有文档，
新建仍用客户端带空间的PUT，不提供批量删除或自动纠错。

列表支持kind（含聚合`knowledge`）、project、q（标题/路径）、status、sort、
limit（1–50）和offset。跨空间排序后统一分页，读取原空间内容，不混入继承副本。
后台管理员可看目录中的所有空间；Agent多空间检索继续按实时授权和原预算隔离。

检索诊断请求：

```json
{
  "read_namespaces": ["shared"],
  "project": "demo",
  "scenario": "优化客户端规则，HTTP服务只是背景"
}
```

报告只返回最多20个候选和每候选16个命中项，并明确总数；包括得分、字段、
符号亲和、选择结果、读取来源和计划加载字符数，不返回整个记忆库正文。
没有保存查询或自动发起评测；分数不是置信概率。只有明确背景/示例子句被排除，
普通提及仍参与竞争，同分歧义继续返回候选。

模板检查请求包含namespace、模板path和待检查document；模板必须在目标空间真实存在。
Agent `/v1/check-template` 则沿用已授权模板继承，并标注真实模板来源及SHA。
模板/文档每项最多256KiB，结构不匹配返回`passed:false`，不会写入记忆。

## 成本边界

后台实际文档保存记录为`maintenance`，命令为`admin-document-put`；重复调用和失败都计成本，
幂等重放没有提交耗时样本。预览、显式模板检查、后台诊断、统计和容量查询不进入日常调用统计，
因此这些数据不代表全部管理开销。统计不覆盖代理、鉴权/解析、浏览器耗时或模型思考。
没有数据库迁移、后台扫描或每轮评分。源码更新不代表服务已部署。
